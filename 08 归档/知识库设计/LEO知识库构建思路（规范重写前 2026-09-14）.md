# LEO 知识库构建思路

## 设计意图
以人生方向组织长期记录，通过整理、实践和复盘积累可复用的知识与方法。交易系统是重点建设模块，其他领域按实际需求发展。

## 核心原则
- 先记录再整理，不确定归属的信息先进入 Inbox。
- 目录承担内容归属，标签、属性与双链支持检索和关联。
- 项目保存实际记录；资源模板保存可复用格式；项目说明连接两者。
- 未开展的方向允许留空，内部层级按需求建立。
- 名称中的编号与文字之间使用空格。

## 目录与职责
| 目录 | 职责 |
| --- | --- |
| 00 Inbox | 临时记录与待处理事项 |
| 01 个人成长 | 学习与技能；工具与方法承接软件操作、资料管理和个人工作流 |
| 02 专业事业 | 工作、项目与职业发展 |
| 03 财富投资 | 资产概况，以及研究、交易、复盘与知识积累 |
| 05 生活健康 | 生活、体态、健康等记录 |
| 06 认知思维 | 思维模型和方法论 |
| 07 资源模板 | 各领域模板、项目说明模板与公共代码片段 |
| 08 归档 | 历史资料、测试与旧版设计 |
| 09 知识库管理 | 架构决策、管理规范、公共功能数据与说明 |

工具系统已并入 `01 个人成长/工具与方法`，其他顶层编号保持原样，不为连续编号重命名。

## 内容工作流
信息进入 Inbox → 明确需求与归属 → 在领域项目中记录实践 → 定期复盘 → 提炼方法、规则和模板 → 归档历史内容。

已有项目使用 `项目说明.md` 说明用途、目录分工、工作流程和模板入口。使用完整路径双链区分各目录下同名的项目说明。新项目可使用 [[07 资源模板/项目管理/项目说明模板|项目说明模板]]。

## 模板管理
统一入口：[[07 资源模板/项目说明|资源模板说明]]。
- `日常记录/`：收件箱条目、日常记录模板。
- `财富投资/交易系统/`：交易日志模板。
- `公共片段/`：滚动引用代码与使用说明。
- `项目管理/`：项目说明模板。

具体领域的模板按实际需要增加；模板需求与设计讨论保存在对应项目中。保留现有模板文件名和版本后缀，实际记录使用业务标题或日期命名。

项目说明中的链接用于打开模板。实际使用时复制或插入模板内容，并保存到项目指定目录；嵌入显示不等于创建独立记录，模板更新也不会自动修改既有记录。

## 交易系统
`03 财富投资/02 交易系统` 分为：
- `01 动态交易系统`：交易日志、周月年复盘、市场环境分析、行业池。
- `02 投资知识体系`：投资知识、方法和规则。
- `03 研究数据库`：研究资料与结论。
- `04 反面错误案例`：错误反馈和改进措施。

交易日志保存到 `01 动态交易系统/01 交易日志`，建议命名为 `YYYY-MM-DD 交易日志.md`；复盘保存到 `01 动态交易系统/02 周、月、年复盘`。
当前交易日志模板已包含滚动引用，正文尚待完善；周、月、年复盘模板尚未建立。详见 [[03 财富投资/02 交易系统/项目说明|交易系统说明]]。

## 公共功能：滚动引用
数据源保存在 [[09 知识库管理/工具/滚动引用/引用数据库|引用数据库]]，复用代码保存在 [[07 资源模板/公共片段/滚动引用模板片段(v1.0)|滚动引用片段]]。
带有对应 DataviewJS 代码的笔记，可按标签或路径匹配语录并每五秒切换。需要 Dataview 支持，普通笔记不会自动获得此功能。代码目前通过复制复用，修改片段后，已有副本需按需更新。

## 协作约定
- 修改前阅读首页、项目说明和相关模板；以当前目录为准。
- 除用户要求重构外，保持顶层结构和编号。
- 不删除用户内容；历史设计保存在归档中。
- 不修改 `.gitignore`，除非用户要求调整同步策略。
- 不修改 `.obsidian/` 下除 `workspace.json` 外的配置，除非用户另有明确授权。
- 仓库原有约定要求修改后同步 GitHub；同步应尊重当前用户授权范围，避免夹带与任务无关的既有修改。
