# LEO 知识库构建思路

> 本文解释知识库为什么这样建设、各部分如何协作，以及今后如何演进。目录与正文的具体写法见 [[文件架构和文档内容结构设计]]；字段、日期、标签与数据质量要求见 [[LEO知识库数据管理规范]]。

## 1. 定位与目标

这是一套围绕个人生活、学习、事业和投资建立的长期知识管理系统。它以实际问题和持续实践为起点，将零散信息转化为可检索的记录、可解释的判断和可复用的方法。

建设目标：
1. 降低记录门槛，让有价值的信息有处可放。
2. 让每个持续开展的项目有清晰入口、记录位置与工作流程。
3. 将实践结果反馈到知识、规则和下一步行动中。
4. 保留事实、来源和历史，使结论可以回看、修正和验证。
5. 保持文件可迁移、结构可理解，避免维护成本超过使用价值。

交易系统是当前深入建设的模块。其他领域按实际需求发展，不要求达到同样的复杂度。

## 2. 设计原则与取舍

| 原则 | 具体做法 | 取舍 |
| --- | --- | --- |
| 先记录，再整理 | 未确定归属的信息先放 Inbox | 允许临时不完整，但定期处理 |
| 按人生领域组织 | 用目录表达主要归属 | 跨领域内容通过链接关联，不重复复制 |
| 按需增加结构 | 稳定出现一类记录后再增加目录或模板 | 不预建大量空目录和复杂字段 |
| 内容与模板分离 | 项目存实例，资源模板存格式 | 模板升级不自动覆盖历史记录 |
| 说明与内容同行 | 项目说明解释本项目的目录和流程 | 不在每个叶子目录重复说明 |
| 数据与展示分离 | Markdown 保存内容，查询与插件辅助展示 | 插件失效时仍能阅读原文 |
| 事实与判断分开 | 保留来源、观察、解释和行动 | 不将推测写成已经证实的事实 |
| 历史可追溯 | 重要重构记录原因，旧设计归档 | 归档不是现行规范 |

## 3. 总体架构

### 3.1 领域与公共支撑

| 区域 | 职责与边界 |
| --- | --- |
| `00 Inbox` | 信息与任务的统一收集入口，承接尚未归类、尚待加工的内容 |
| `01 个人成长` | 学习、技能、工具使用和个人方法；工具内容位于 `工具与方法/` |
| `02 专业事业` | 工作项目、职业经验与专业成果 |
| `03 财富投资` | 资产概况、投资研究、交易记录与复盘 |
| `05 生活健康` | 生活安排、体态、运动与健康相关记录 |
| `06 认知思维` | 可跨项目复用的认知模型、决策原则与方法论 |
| `07 资源模板` | 集中存放记录模板、项目说明模板和公共代码片段 |
| `08 归档` | 已结束、不再沿用或供历史追溯的内容 |
| `09 知识库管理` | 库自身的架构、规范、公共数据和功能维护说明 |

原工具系统已合并到个人成长。目录编号用于固定同级展示顺序，采用“两位编号 + 空格 + 名称”，在各父目录内独立安排。保留其他目录编号，编号不连续不影响使用。顶层文件 `首页.md` 提供入口，`README.md` 提供仓库简介。

### 3.2 组织工具的分工

- **目录**回答“这份内容主要属于哪里”。每份内容确定一个主要归属。
- **项目说明**回答“这个项目怎么使用、记录放哪里、从哪个模板开始”。
- **属性**记录类型、时间、状态等可查询信息。
- **标签**提供跨目录主题检索，不复制完整目录树。
- **双链**连接项目、记录、来源和结论。
- **模板**约束重复任务的最低记录格式。
- **Dataview 等插件**提供查询和展示，不作为唯一内容存储位置。

### 3.3 工具学习与知识库管理的边界

Obsidian 操作、Markdown 使用、软件技巧属于个人成长中的工具与方法；本库的命名规则、目录决策、数据格式、共享语录库属于知识库管理。遇到同时涉及两者的内容，按主要用途保存，另一处用链接引用。

## 4. 内容如何流转

### 4.1 收集

记录问题、想法、材料或事件，至少留下能理解的正文。临时速记不因缺少属性而被阻止。需要处理的内容标为 `pending`，必要时记录来源和下一步。

### 4.2 整理

回顾 Inbox 时，判断内容是否需要行动、长期保存或进一步研究：
- 一次性事项：完成后补充结果，按需要保留或归档。
- 持续性任务：移入对应领域，形成项目或加入已有项目。
- 可复用结论：写成主题笔记，并链接实践依据。
- 尚不能判断：保留在 Inbox，写明待解决的问题。

目录位置与任务状态分别记录。笔记仍在 Inbox 不代表任务一定未完成，写完一篇日志也不代表其所在项目已经完成。

### 4.3 实践与反馈

项目说明 → 使用模板创建记录 → 保存事实与过程 → 汇总复盘 → 更新知识、规则和行动。

复盘不是把日常记录重复一遍，应说明结果差异、原因、证据以及下一次如何调整。跨周期引用原始记录，避免多处维护同一事实。

### 4.4 归档

停止维护的项目或被替代的设计可移入归档，保留来源项目、时间和替代文档链接。需要重新使用时可以恢复。删除内容需要明确意图，不能以“整理”为由默认清除历史记录。

## 5. 模板与项目说明

统一模板入口是 [[07 资源模板/项目说明|资源模板说明]]。模板只保存可复用格式、提示和必要示例；实际日期、结果、持仓等实例数据保存在项目记录中。

每个有独立目标或工作流程的项目设置 `项目说明.md`，包括用途、目录分工、工作流程、模板入口和记录保存位置。普通资料目录或按月份分组的目录不必逐一增加说明。

项目说明中的模板链接用于打开参考；复制或插入模板后才能形成独立记录。模板迭代只影响后续创建的内容，历史笔记按需要迁移，不能批量覆盖。

## 6. 当前重点：交易系统

[[03 财富投资/02 交易系统/项目说明|交易系统]] 当前划分为：
1. 动态交易系统：交易日志、周期复盘、市场环境和行业池。
2. 投资知识体系：方法、知识、纪律和规则。
3. 研究数据库：研究资料与结论。
4. 反面错误案例：错误过程、成因与防范措施。

设计上的反馈关系是：研究支持判断，日志记录执行，复盘检查结果，知识体系保存方法，错误案例帮助修正规则。

这些目录不等于功能已经完成。当前交易日志模板包含滚动引用，但正文仍待完善；周、月、年复盘模板尚未建立。数据汇总和可视化应在记录字段稳定后再开展。

## 7. 技术与可维护性

正文以 UTF-8 Markdown 保存，附件使用文件引用，Obsidian 提供编辑和链接体验。Git 用于版本追踪，不能代替所有备份；空目录不会被 Git 单独保存。

滚动引用的数据保存在 [[09 知识库管理/工具/滚动引用/引用数据库|引用数据库]]，复用代码位于 [[07 资源模板/公共片段/滚动引用模板片段(v1.0)|滚动引用片段]]。只有插入对应代码且具备 Dataview 支持的笔记才会展示轮播。现阶段代码采用复制复用，更新源片段后已有副本不会自动变化。

优先改善内容组织，再增加插件、查询或自动化。新增功能必须有明确使用场景、可维护的数据来源和失败时的阅读方式。

## 8. 演进与协作

- 日常使用：补充记录、链接和必要属性。
- 定期回顾：处理 Inbox、更新项目说明、提炼重复出现的记录格式。
- 结构调整：确认目标，检查引用，迁移内容，更新说明，验证链接，记录变化。
- 规范调整：同步检查三份规范及有关模板；存在尚未迁移的内容时明确标注。
- 协作编辑：先看项目说明和相关模板，尊重用户正在进行的修改，不顺带重构无关内容。
- 配置与同步：沿用当前配置和忽略策略；修改配置需有任务依据。提交或同步时明确范围，不夹带无关修改，不把敏感内容纳入公开同步。

判断是否需要增加结构的标准：它是否能解决反复出现的问题，是否减少寻找或记录成本，是否有能力持续维护。

## 9. 规范关系与实施状态

[[文件架构和文档内容结构设计]] 负责目录、命名、正文骨架和链接；[[LEO知识库数据管理规范]] 负责字段、类型、时间、状态、数据质量与安全。三者是同一套规范；若出现冲突，应修正文档，具体用户任务要求优先。

本次规范用于今后新建和整理后的笔记。旧笔记和模板存在历史格式，按使用频率逐步迁移，不表示全库已经符合新规范。
