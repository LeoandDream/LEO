# 文件架构和文档内容结构设计

## 2. 文件归属决策

| 内容 | 保存位置 |
| --- | --- |
| 尚未明确归属的信息和需求 | Inbox |
| 具体项目的过程、成果、设计讨论 | 所属领域的项目目录 |
| 学习笔记和工具操作 | 个人成长及其子项目 |
| 可供多个项目复用的记录格式 | 资源模板，按用途分类 |
| 知识库自身的规则与共享功能数据 | 知识库管理 |
| 已停用但需追溯的内容 | 归档，尽量保留原项目语境 |

一个文件有一个主要归属。跨项目使用时链接到原文；只有明确需要独立演化的副本才复制，并注明来源。

## 3. 目录层级与命名

### 3.1 目录

编号用于固定同级目录的展示顺序。顶层保持现有编号与名称；新增项目目录和需要排序的内容子目录采用“两位编号 + 空格 + 名称”，例如 `01 灵巧手物流分拣`、`01 交易日志`。编号在各自父目录内独立安排，不表示进度、时间或优先级。新增时按期望顺序确定编号，不为了编号连续而移动其他领域；调整已有编号时同步检查链接。附件等功能目录可保留固定名称，现有未编号目录在明确整理时再统一。

没有统一的最大层数。仅在记录数量、不同流程或明确语义需要时增加一层；避免只有一个文件却连续嵌套多个含义相近的目录。

新的按月记录目录使用 `YYYY-MM`，例如 `2026-09`；已有 `2026-6、7` 保持历史名称，迁移时再统一。

### 3.2 文件

| 类型   | 建议命名                         |
| ---- | ---------------------------- |
| 项目入口 | `项目说明.md`                    |
| 主题知识 | `主题名称.md`                    |
| 单日记录 | `2026-09-14 交易日志.md`         |
| 周复盘  | `2026-W38 交易复盘.md`           |
| 月复盘  | `2026-09 交易复盘.md`            |
| 年复盘  | `2026 年度交易复盘.md`             |
| 研究分析 | `对象或主题 研究分析.md`，重复更新的快照加日期前缀 |
| 模板   | `用途模板.md`                    |
| 历史设计 | `原名称（调整前 YYYY-MM-DD）.md`     |
|      |                              |

周编号采用 ISO 周，可能与自然年边界不同；周期范围以笔记属性为准。文件名使用空格替代分隔用下划线，代码、外部文件名和引用原文中的下划线不强制替换。

避免含糊的 `新建文档`、`最终版2`、`测试最新版`；避免 Windows 不支持的字符 `\ / : * ? " < > |`、末尾空格和末尾句点。示例占位符不能原样用作文件名。

模板新版本优先在 `version` 属性记录。已有 `(v1.0)` 后缀兼容保留；需要并行维护不兼容版本时才增加版本文件，并在入口说明推荐版本。

## 4. 通用文档结构

新建正式笔记采用以下顺序：
1. 顶部 YAML 属性区，字段遵循数据规范。
2. 一个一级标题，表达文档主题。
3. 简短摘要或用途说明，需要时添加。
4. 按文档类型组织的正文。
5. 来源、关联记录或下一步行动，按需要添加。

一级标题原则上只有一个；二级标题划分主要部分，三级标题细分，不为视觉大小跳过层级。文件名与标题主题一致；同名 `项目说明.md` 的标题可写成“交易系统 · 项目说明”以区分。

短笔记可以只有标题与正文；模板提供提示，但不要求保留所有空章节。复杂文档使用小节与表格，不堆叠装饰、重复摘要或无用途的分隔线。

## 5. 按文档类型组织正文

### 5.1 项目说明

至少说明以下内容：
- **用途与边界**：目标、管理范围；有终点的项目写明完成标准。
- **目录说明**：各目录保存什么，避免重复介绍所有文件。
- **工作流程**：从需求、执行到复盘的步骤。
- **模板入口**：完整路径链接、适用场景、新记录保存位置。
- **关联资料**：上级说明、依赖项目和关键知识。

仅独立项目或有独立流程的模块需要说明文档。叶子目录的含义能由上级说明解释时，不重复创建。参考 [[07 资源模板/项目管理/项目说明模板|项目说明模板]]。

### 5.2 Inbox 条目与日常记录

Inbox 条目：一句话速记 → 内容或材料 → 待处理问题 → 下一步与归属 → 来源。
日常记录：当天事项 → 结果或感受 → 未完成事项及下一步。
普通事件保持简短，重要事件再独立成篇。

### 5.3 知识与工具笔记

问题或用途 → 核心结论 → 解释或操作步骤 → 示例与适用边界 → 来源与相关实践。
工具步骤应写清环境、前提和验证方式。命令置于带语言标记的代码块，说明输入和预期结果；不把运行中临时状态当作长期结论。

### 5.4 研究分析

研究问题 → 数据范围与来源 → 事实观察 → 推理与假设 → 结论 → 不确定性与更新条件。
对同一对象持续维护时区分“当前观点”与“历史快照”，重大结论变化说明原因，不抹去原先判断依据。

### 5.5 交易日志

建议正文：市场环境及相关分析 → 当日计划 → 操作记录 → 持仓变化与跟踪 → 情绪与纪律检查 → 当日总结和下一步。
交易表按一行一笔成交记录，数字格式见数据规范；交易前判断与交易后解释分开。市场分析已有专门笔记时用链接引用，避免复制多份。
这是正文设计要求；现有交易日志模板尚未补齐这些部分。

### 5.6 周期复盘与错误案例

周期复盘：周期范围 → 目标与结果 → 关键事件及证据 → 有效做法与问题 → 原因 → 下一周期行动。
错误案例：事件背景 → 当时依据 → 实际行为和结果 → 错误机制 → 改进措施 → 后续验证。
行动应能执行和检查，避免仅写“更加自律”“继续努力”。

### 5.7 模板与公共片段

模板包含可复用的属性和正文骨架；维护说明写清用途、输出位置和占位符处理方式。模板里的示例应明确标为示例，不得与真实记录混淆。
公共片段说明依赖、数据源、插入方式及维护注意事项。模板设计讨论留在所属项目，通过链接关联模板。

## 6. 链接与附件

- 库内关联使用双链；目标重名、目标是项目说明或跨目录模板时，使用相对知识库根目录的完整路径。
- 模板链接示例：[[07 资源模板/日常记录/收件箱条目模板(v1.0)|收件箱条目模板]]。
- `![[文件名]]` 用于嵌入展示；不要把嵌入模板当作可独立填写的实例。
- 外部资料使用带描述的 Markdown 链接，并在正文说明来源和引用用途。
- 新附件沿用当前 `./附件` 设置，即笔记所在目录下的附件子目录；现有图片目录保留。
- 附件用可识别的名称，例如 `2026-09-14 市场走势.png`。跨目录引用或存在同名文件时写完整路径。
- 移动笔记时检查相对附件链接、双链、嵌入、Dataview 路径和脚本内硬编码；不能仅依赖软件自动更新。

## 7. 调整目录的流程

1. 确定旧路径、新路径及调整理由，检查目标是否重名。
2. 查看相关链接、查询和配置，确认是否需要同步修改。
3. 迁移原文件，保留内容与附件，不以复制后遗留两份的方式完成迁移。
4. 更新项目说明、首页和有关规范；模板迁移同步更新入口。
5. 检查新链接、旧路径残留及必要的展示效果。
6. 重要调整保留旧版说明或变更记录，归档内容标识为历史。

## 8. 创建与整理检查

- 文件归属清楚、名称可辨识。
- 正文能独立说明主题，事实与结论可区分。
- 新建正式笔记的基本属性完整，时间和标签格式一致。
- 模板链接可打开，新记录有明确保存位置。
- 附件、来源及关联记录可找到。
- 不引入未实现功能的描述，不覆盖用户既有内容。

旧笔记按实际整理逐步对齐；本规范不要求立即重命名历史文件或补齐全部空目录。
